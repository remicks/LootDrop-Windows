# LootDrop Windows v2 0.7.8 — store sign-in shortcuts

Added a Store sign-in section for Steam, Epic Games, GOG, Ubisoft and itch.io. Each button opens a fixed official HTTPS website in the default browser. The complete initial URL is visible. GOG uses its homepage's Sign in action; Ubisoft uses its account entry point. No feed/import can replace these destinations. There is no embedded browser, password field, token vault, cookie import, automatic sign-in, two-factor bypass or automatic claiming.

The privacy explanation explicitly states that LootDrop does not collect, store or transmit store passwords/cookies/sign-in tokens. Browsers transmit credentials to the store or its chosen identity provider to authenticate. Remembered sessions are managed by the browser/store; browser-account sync can move saved information off-device when enabled. It would be inaccurate to promise that all credentials are always local or never transmitted. Use the same browser profile for sign-in and offer pages. LootDrop cannot determine whether the browser is signed in.

Security hardening: reject invisible Unicode formatting characters in external URLs; validate null/oversized stored filter lists and names before using them; explicitly disable offers with Expired or ReportedNotFree verification states; prevent cached offers from initiating price verification. Existing 0.7.7 compact grid and claim-preview restrictions are preserved.

Validation: 375 regression checks passed, including 2,000 deterministic malformed URL inputs, five fixed launch targets, invalid identifier/tampered button handling, no credential inputs or data writes from viewing sign-in, privacy wording, section navigation and two window widths. The complete existing transport, library, backup, identity, layout, theme/contrast and offline tests ran. Actual XAML was rendered headlessly and inspected. Debug and Release locked restores and live direct/transitive vulnerability listings completed without advisory findings. Both build scripts parsed and a simulated failed audit stopped release publishing. See SECURITY-REVIEW-0.7.8.md and audit-evidence/0.7.8/ for scope, results and unresolved risks.

Packages are unsigned. Native browser handoff, real sign-in/claim, installer/update/uninstaller, clean-machine launch, full screen-reader testing and independent penetration testing remain unperformed. No real account credentials, personal library, startup registration, beta or iOS files were accessed or modified by the tests. No claim of maximum safety, comprehensive absence of vulnerabilities or distribution clearance is made.

Final packaging validation: version 0.7.8.0; fresh locked audited restore, Release publish and Inno compilation succeeded. Portable archive contains one executable matching the fresh published executable by SHA256. App signature: NotSigned; installer signature: NotSigned. Neither was installed or launched.
